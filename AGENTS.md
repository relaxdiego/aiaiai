# aiaiai: AI session orientation

This repo runs the model backend for coding agents on a workstation (Linux or macOS). It runs LiteLLM, SearXNG, and Postgres under process-compose. LiteLLM serves Claude models from the user's GitHub Copilot subscription. The agents themselves run in a separate VM and reach LiteLLM over HTTP. The repo never configures clients and writes nothing outside its own directory.

## What each file does

| File | Purpose |
|------|---------|
| `Makefile` | User entry points: `setup`, `copilot-login`, `serve`, `start`, `stop`, `status`, `new-key`, `show-key`, `show-base-url` |
| `scripts/setup.sh` | Wizard. Asks listen address and budget. Merges them into `.envrc.local`, generates secrets once, renders templates, installs devbox packages and LiteLLM, initializes `data/postgres`, and signs in to Copilot when stdin is a terminal |
| `scripts/copilot-login.sh` | Runs LiteLLM's Copilot device flow with tokens in `data/github_copilot`. Refreshes the short-lived key when a token exists |
| `scripts/serve.sh` | Checks setup ran, warns when Copilot is not signed in, loads devbox and `.envrc.local`, execs `process-compose up`. Used by `serve` and `start` |
| `scripts/new-key.sh` | Mints a LiteLLM virtual key through `/key/generate` |
| `process-compose.yaml` | Postgres, SearXNG, LiteLLM with readiness probes and bounded log rotation. Interpolates `${LITELLM_HOST}` and `${POSTGRES_PASSWORD}` from the environment |
| `litellm/config.yaml.example` | Committed template: priced Copilot model registry, auth, DB, budget, web-search interception. `__LITELLM_MAX_BUDGET__` placeholder |
| `searxng/settings.yml.example` | Committed template: loopback bind, limiter off, JSON API on |
| `litellm/config.yaml`, `searxng/settings.yml` | Generated by `make setup`, git-ignored, never hand-edit |
| `.envrc.local` | Git-ignored, mode 600. The only file with generated secrets |
| `data/github_copilot/` | Git-ignored, mode 700. The GitHub access token and the short-lived Copilot key |
| `.envrc.local.example` | Every variable `.envrc.local` holds, with placeholders |
| `.envrc` | Optional direnv hook: devbox shellenv plus `.envrc.local` |
| `devbox.json` | python, uv, searxng, process-compose, postgresql |
| `requirements.in` / `requirements.txt` | LiteLLM and Prisma pins / hash-locked lockfile from `uv pip compile --generate-hashes --exclude-newer` |
| `.agent/skills/validate-aiaiai/` | Validation skill, helper script, and feature map. `.claude/skills` and `.pi/skills` symlink here |

## Validate before committing

Run the `validate-aiaiai` skill after any change to the files above. It is the definition of done. A change that adds or alters a make target, setup prompt, or endpoint also updates `features/` and `scripts/validate.sh` in the same commit.

## Key design decisions

**Server only.** Earlier versions had a client mode that edited `~/.claude/settings.json`. It is gone. Clients in the VM configure themselves. The README shows how.

**One listen address.** LiteLLM binds to `LITELLM_HOST`, chosen in setup. LiteLLM's own default is `0.0.0.0` (`litellm/proxy/proxy_cli.py`, `--host`), which would expose it to every network, so the address is always passed explicitly. SearXNG and Postgres stay on loopback because only LiteLLM talks to them.

**Per-agent virtual keys.** Agents get keys from `make new-key` instead of the master key, so spend is tracked per agent and a key can be revoked alone. Virtual keys need a database, hence the bundled Postgres on port 5439. LiteLLM applies its Prisma schema on first start.

**Setup merges, never overwrites.** `set_envrc_var` replaces one `export VAR=` line at a time. Secrets are generated only when missing. User-added lines survive. Variables from old versions (`RETIRED_VARS`) are removed with a warning.

**No direnv dependency at runtime.** `scripts/serve.sh` loads devbox and `.envrc.local` itself, so `make start` works from a plain shell, a login script, or a service manager.

**Generated config from committed templates.** Edit `*.example`, re-run `make setup`. `max_budget` is rendered as a literal. LiteLLM before v1.90.0 did not coerce an env-sourced `max_budget` to a number (BerriAI/litellm#23843). The pinned version does, but the literal keeps the rendered config readable on its own.

**Pinned runtime.** `requirements.in` pins `litellm[proxy]==1.100.1`. `requirements.txt` locks every transitive dependency by hash and is compiled with `--exclude-newer` at the release date, so nothing uploaded later can slip in. LiteLLM also fetches its model cost map, Anthropic beta headers, blog posts, and policy templates from GitHub `main` at runtime. `process-compose.yaml` sets `LITELLM_LOCAL_MODEL_COST_MAP`, `LITELLM_LOCAL_ANTHROPIC_BETA_HEADERS`, `LITELLM_LOCAL_BLOG_POSTS`, and `LITELLM_LOCAL_POLICY_TEMPLATES` so it uses the copies bundled in the pinned wheel instead.

**GitHub Copilot backend.** The `github_copilot` provider authenticates with GitHub's device flow (`litellm/llms/github_copilot/authenticator.py`). It keeps a long-lived GitHub token in `access-token` and a Copilot key of about 30 minutes in `api-key.json`. Its default directory is `~/.config/litellm/github_copilot`. `GITHUB_COPILOT_TOKEN_DIR=data/github_copilot` in `process-compose.yaml` and `scripts/copilot-login.sh` keeps both files inside the repo. `make setup` signs in only when stdin is a terminal, because the flow waits for a person to enter a code. LiteLLM authenticates each Copilot deployment while it loads the config (`get_llm_provider` calls `Authenticator.get_api_key`). A server started without a token therefore runs the device flow inside the server and drops every model it cannot sign in. `scripts/serve.sh` warns about a missing token but still starts, so the validator can run with a key fixture and no account.

**Priced model registry.** `litellm/config.yaml.example` is the one source of truth for which models agents can call and what they cost. Each entry maps a Claude Code model ID to a Copilot model with GitHub's published input, output, cache-read, and cache-write prices in `litellm_params`, where `/model/info` reports them. `max_budget` and per-key budgets then measure real Copilot spend. There is no wildcard route, because an unpriced model would bill at 0 and escape every budget.

**Web search.** Copilot has no native web search. With `github_copilot` in `websearch_interception_params.enabled_providers`, LiteLLM recognizes Claude Code's standalone `web_search` request and answers it from SearXNG before any Copilot call (`_try_websearch_short_circuit` in `litellm/llms/anthropic/experimental_pass_through/messages/handler.py`). Other clients call `POST /v1/search/local-search`. Both find SearXNG through `SEARXNG_API_BASE`, set in `process-compose.yaml`.

**Fixed ports.** 4000, 8888, 5439, and socket `/tmp/aiaiai-<uid>.sock`. One instance per machine. The validator refuses to run when they are busy.

## Invariants to maintain

- No committed file contains a real secret. Generated secrets live only in `.envrc.local`, and Copilot tokens only in `data/github_copilot`. The repo is public.
- `.envrc.local`, rendered configs, `data/`, and `logs/` stay git-ignored.
- The Copilot token directory stays under `data/`. Nothing writes to `~/.config/litellm`.
- Every model in the registry carries all four prices. No wildcard route.
- LiteLLM binds only to `LITELLM_HOST`. SearXNG and Postgres bind only to `127.0.0.1`.
- `make setup` stays idempotent and keeps existing secrets, the Copilot sign-in, and user lines.
- `make start` and `make serve` fail with a pointer to `make setup` when setup has not run.
- Scripts stay compatible with macOS's bash 3.2: no `${var,,}`, `mapfile`, or associative arrays.
- `requirements.txt` is only regenerated from `requirements.in` with the uv command in its header, hashes and `--exclude-newer` included.
- LiteLLM runs with the four `LITELLM_LOCAL_*` variables set, so it never loads runtime data from GitHub.
- process-compose log rotation stays bounded.
